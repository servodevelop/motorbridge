02实施成果：从协议接入到工程交付

接入工作围绕“统一接口可复用、设备行为可验证、现场操作可落地”展开，将厂商协议能力转化为 motorbridge 中一致的控制与数据服务。

  1. MILESTONE 01 / 协议梳理

    建立可执行的功能映射

    交叉核对 CAN/UART 协议、各语言 SDK 与官方网页工具，明确角度、速度、电流、温度及参数编号，完成位置控制、状态反馈、原点和配置操作的映射。

  2. MILESTONE 02 / 双协议复用

    一次接入，沿用整套应用接口

    以 FashionStar 同一厂商下的 CAN、UART 型号承载协议差异；核心按帧类型复用，贯通 Rust、C ABI、Python、C++ 与 WebSocket，统一运动单位、参数访问及设备生命周期。

  3. MILESTONE 03 / 传输扩展

    连接标准 CAN 与 UC-06 设备生态

    完成 UC-06 初始化、串口封装、CAN 速率选择、状态解析和多设备通信，复用现有 CAN 电机控制逻辑；用户按转接板选择连接入口即可调用相同功能。

  4. MILESTONE 04 / 真机闭环

    用设备反馈完善控制与通信

    落实加减速参数、置零操作顺序、串口发送时序、并发访问与配置切换规则。通过多速度、多圈、双机、全速率和断电重连测试，逐项核对控制结果与配置保存。

交付价值

应用获得一致的设备操作方式，现场获得清晰的接线与命令步骤，维护人员获得完整的参数语义和可追溯的验收数据。

04协议实现与统一数据映射

CAN：寄存器访问与两类转接板

  • 标准 USB CAN 与 UC-06 共用 CAN 电机驱动；UC-06 完成 USB 串口与 CAN 报文转换。
  • 经典 CAN 标准帧，仲裁 ID 为 0x321，数据区携带 ServoID。
  • 实现单寄存器及双寄存器读写，组合多圈角度、序号等 32 位参数。
  • 实现运动参数块 0x50–0x59 的原始读写，覆盖时间、目标角度、功率、加减速时间、速度与执行控制。
  • 提供阻尼功率、圈数重置、原点及参数复位的寄存器操作入口。
  • 受保护 PID 区域 0xC8–0xD5 的访问由驱动完成解锁、操作与复锁。

UART/RS-485：原生串口协议链路

  • 使用 transport=uart、8-N-1 和显式串口波特率；SDK 创建入口默认 115200。
  • 实现请求/回应帧、长度检查、累加校验、分包组包及噪声重同步。
  • 原生 0x0F 位置命令携带速度上限；加速和减速时间均为协议下限 20 ms，执行功率使用设备配置上限。
  • 原生 0x16 监控回包集中提供位置、电流、温度、状态等数据。
  • 同一控制器下的总线事务串行执行，发送间隔至少 5 ms；低波特率时根据请求与回应长度增加间隔，回复按命令、ServoID、参数地址和长度匹配。

A. UART / RS-485 舵机

第 1 步 · 接线，确认电脑上的设备名称

电脑 USB → UART 或 RS-485 适配器 → 舵机；按舵机规格接通外部电源。

按舵机型号选择匹配的 UART 电平或 RS-485 适配器，并按接线图连接信号、参考地和电源。适配器应支持自动半双工收发，驱动使用 8-N-1 串口格式。

终端 · 查看 USB 串口名称
ls /dev | grep -E '^(ttyUSB|ttyACM)'

例如输出 ttyUSB0，对应的完整端口名就是 /dev/ttyUSB0。有多个端口时，可对比插入转接板前后的列表，找到新增的一项。

本路线以 /dev/ttyUSB0、115200 baud 为例。把所有命令中的端口与速率改成实际值；设备若已设为 1M，使用 --serial-baud 1000000。

第 2 步 · 扫描舵机，记下设备编号

终端 · 扫描 ID 0～10
./target/release/motor_cli --vendor fashionstar --model uart --transport uart \
  --serial-port /dev/ttyUSB0 --serial-baud 115200 \
  --mode scan --start-id 0 --end-id 10

完成标志：出现 [hit] 行。probe=0x00 表示 ID 0，probe=0x01 表示 ID 1，probe=0x05 表示 ID 5，probe=0x0A 表示 ID 10。下文以 ID 0 继续，其他编号修改 --motor-id 后执行。扫描范围可通过 --start-id 和 --end-id 在 0～254 内调整。

第 3 步 · 先读取一次当前状态

终端 · 读取 ID 0 的位置、电流与温度
./target/release/motor_cli --vendor fashionstar --model uart --transport uart \
  --serial-port /dev/ttyUSB0 --serial-baud 115200 \
  --motor-id 0 --mode status

完成标志：出现包含 pos、vel、current、temp 和 status 的一行数据。字段含义见下方“读懂反馈”。

第 4 步 · 转到 90°，连续观察反馈

示例目标是相对已保存零点的绝对 90°，速度上限为 30°/s。在命令中分别写为 --pos 1.5707963 和 --vlim 0.5235988；按机构允许的角度调整目标。从 0° 出发约需 3 秒，下面两条命令依次发送目标、采集 150 次反馈。

终端 · 整块执行：发送目标，随后持续读取状态
./target/release/motor_cli --vendor fashionstar --model uart --transport uart \
  --serial-port /dev/ttyUSB0 --serial-baud 115200 \
  --motor-id 0 --mode pos-vel --pos 1.5707963 --vlim 0.5235988

./target/release/motor_cli --vendor fashionstar --model uart --transport uart \
  --serial-port /dev/ttyUSB0 --serial-baud 115200 \
  --motor-id 0 --mode status --loop 150 --dt-ms 40

观察结果：pos 随转动变化，90° 对应约 +1.57080 rad；到位后位置稳定，vel 接近 0。--loop 150 表示读取 150 次，--dt-ms 40 表示两次查询之间等待 40 ms，整段采集约 6 秒以上。

第 5 步 · 停止保持，结束后卸力

stop 让舵机停止并保持当前位置。在反馈循环中，可先按 Ctrl+C 结束终端采样，再执行停止命令；结束采样后，舵机继续执行已下发的目标。

终端 · 停止并保持当前位置
./target/release/motor_cli --vendor fashionstar --model uart --transport uart \
  --serial-port /dev/ttyUSB0 --serial-baud 115200 \
  --motor-id 0 --mode stop

结束使用时执行 disable，舵机释放输出，转轴进入卸力状态。

终端 · 卸力
./target/release/motor_cli --vendor fashionstar --model uart --transport uart \
  --serial-port /dev/ttyUSB0 --serial-baud 115200 \
  --motor-id 0 --mode disable

本路线完成：已完成设备发现、状态读取、限速位置控制和卸力。下一次使用时，沿用对应的完整命令并修改目标角度即可。

B. CAN 舵机 + 标准 USB CAN

第 1 步 · 接线，确认电脑上的设备名称

电脑 USB → PCAN / CANable → CANH、CANL → CAN 舵机；按舵机规格接通外部电源。

CANH 接 CANH，CANL 接 CANL，总线两端各配置 120 Ω 终端电阻。Linux 通过 SocketCAN 使用转接板；CANable 的 candleLight / gs_usb 固件提供这种接口。

终端 · 查看 CAN 接口
ip -brief link

找到 can0 这一项；若实际名称为 can1，将本路线中的 can0 全部替换为 can1。

本路线以 can0、1 Mbps 为例。下面的 1000000 是转接板 CAN 侧的速率，应与舵机已有设置一致；500 kbit/s 的舵机使用 500000。

终端 · 将 can0 设为 1 Mbps 并启动
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up
ip -details link show can0

完成标志：输出中出现 UP 和 bitrate 1000000，随后开始扫描舵机。

读懂反馈：每一列是什么意思

三条路线使用相同的输出格式。下面是一行格式示例，具体数值随设备状态变化：

输出示例 · 状态数据
#8 pos=+1.57080 vel=+0.000 current=0.020A temp=32.0C status=0x00
字段怎样理解
pos当前位置，单位 rad（弧度）。0 为零点，1.5708 约为 90°，3.1416 约为 180°。
vel根据相邻位置样本估算的平均速度，单位 rad/s。首条样本显示 NaN 时，继续读取，第二条有效样本起提供速度值。
current舵机电流，单位 A。Python / WebSocket 的对应字段名为 torq，FashionStar 在该字段提供电流。
temp舵机温度，单位 °C；Python / WebSocket 的对应字段名为 t_mos。
status设备状态字，按协议保留原值；Python / WebSocket 的对应字段名为 status_code。

第 2 步 · 将以下代码保存为 fashionstar_demo.py

把文件放在仓库根目录。修改端口和 motor_id，使其与第 05 节扫描结果一致；UART 与标准 USB CAN 的替换方式列在代码下方。

文件内容 · fashionstar_demo.py · 完整示例
import math
import time
from motorbridge import Controller

motor_id = 0
target_degrees = 90
speed_degrees_per_second = 30

# 本例使用 UC-06；端口和 CAN 速率与舵机连接一致。
controller = Controller.from_uc06("/dev/ttyUSB0", 1000000)
model = "fashionstar"

# 离开 with 时，控制器会卸力并释放连接。
with controller:
    motor = controller.add_fashionstar_motor(motor_id, 0x321, model)
    try:
        motor.send_pos_vel(
            math.radians(target_degrees),
            math.radians(speed_degrees_per_second),
        )
        deadline = time.monotonic() + 6.0
        while time.monotonic() < deadline:
            motor.request_feedback()
            state = motor.get_state_snapshot().state
            print(f"位置={math.degrees(state.pos):.1f}° "
                  f"速度={math.degrees(state.vel):.1f}°/s "
                  f"电流={state.torq:.3f} A "
                  f"温度={state.t_mos:.1f} °C")
            time.sleep(0.04)
    finally:
        motor.close()

换一种连接方式：将上面相邻的 controller = ... 和 model = ... 两行替换为对应内容，其余控制和反馈代码沿用。

连接方式controller 这一行model 这一行
UART / RS-485controller = Controller.from_uart("/dev/ttyUSB0", 115200)model = "uart"
标准 USB CANcontroller = Controller("can0")model = "fashionstar"
UC-06controller = Controller.from_uc06("/dev/ttyUSB0", 1000000)model = "fashionstar"

UART 的 115200 填写实际串口速率；UC-06 的 1000000 填写实际 CAN 速率；标准 USB CAN 沿用第 05 节配置好的 can0。add_fashionstar_motor 的三个参数依次是设备 ID、通信标识 0x321、协议型号；UART 也按接口约定填入 0x321。
